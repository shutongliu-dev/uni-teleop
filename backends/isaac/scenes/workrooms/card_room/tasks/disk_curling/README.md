# 推筹得分 · disk_curling

两名玩家从相对的南北发射区轮流推出圆盘，允许盘与已出手盘碰撞，八盘全部停止后按最终位置计分。保留原棋牌室；本任务更换桌面游戏层。双方各四盘，直径 66 mm、厚 18 mm，靶心在世界坐标 `(0.65,0)`。唯一几何、质量配方、初态和区域来源为 `game_designs.design_for`。

黑方先，从南侧沿 +Y 发射，发射线 y=-0.24 m；白方从北侧沿 -Y 发射，发射线 y=+0.24 m。黑方发射区 x∈[0.44,0.86]、y∈[-0.40,-0.26]；白方 x 相同、y∈[0.26,0.40]。每回合选一枚未出手己方盘。有效推进开始前可以在本方区内真实拿起、调整该盘；不得触碰其他盘或获得区外推进，准备不计出手。

准备时所选盘的完整投影须在本方发射区；当盘平躺、有 Deck 支撑、与己方手实际接触且朝目标方向速度达到 0.04 m/s，才开始有效推进。此后只允许一次连续接触，须在本方发射线之前或线上释放，再由盘自由滑过发射线；释放和越线按盘体中心的世界 Y 判定。释放后再次接触为补推，不允许。盘与已发盘之间的碰撞可以改变双方得分；机器人不能直接碰其他盘，手臂接触不能代替己方手。未发盘不计分，须保持准备位置；扰动库存属于出手违规。

必须等所有已发盘都完全释放，并有新鲜连续 300 ms 稳定窗口和完整原生观测，才确认本次出手及允许下一回合。零接触、未自由越线或缺少观测不确认出手。已有盘之后被撞开会改变最终分数，不锁定其初次停下得分。

最终按八枚盘心到靶心的距离计分：

| 半径范围 | 每盘分数 |
|---|---:|
| ≤ 0.06 m | 3 |
| > 0.06 且 ≤ 0.12 m | 2 |
| > 0.12 且 ≤ 0.18 m | 1 |
| > 0.18 m 或盘不再由计分 Deck 承托 | 0 |

恰好在线上的盘计内侧区；盘体覆盖范围不改变本版本按盘心的规则。计分盘须在 Deck 支撑链上平躺，两面朝上均可。出手盘落台后，须在实际声明的非计分静态支持面上完整释放并稳定才按零分结算，允许侧躺；在桌下但 XY 落在靶心的盘也不能计分。没有支撑证据时不能补零完成。双方总分高者胜，相等平局。只在八次出手均确认且最终状态稳定后产生胜负；预算耗尽、取消和运行错误不按当前分数判赢家。

[ExpansionMatch](../../expansion_referee.py) 从连续原生帧记录实际接触、启动／释放位置、释放后越线、其他盘接触、库存保持及最终支持／稳定，随后调用 [DiskCurlingRules](../../expansion_rules.py)。纯规则评分要求明确的 `on_deck` 证据，不能仅靠 XY 计分；上述参数不能来自模型自报。二次补推、越线后才释放、区外启动或碰别盘导致 `incomplete/shot_rule_violation` 且无赢家，真实物理失败另记 `physical_failure`。非法逻辑请求不耗操作 epoch，新请求 ID 不能擦掉已发生的物理违规。

任务已通过认证 `/board-games` 的独立 `bench_card_game_state_v1` 接入。意图为 `shoot_disk(piece_id)`，有效推进后不能取消；每次确认才递增操作 epoch 并换手。Agent 使用 `--family card_room --task task7`；完整合同和启动见[接入指南](../../../../../docs/agent_bench/card_room_expansion.md)。旧三棋种的落子协议不变。

```bash
python -m scenes.workrooms.card_room.tasks.disk_curling.task
```

该入口只输出静态候选。资产构建统一使用 `scripts.assets.build_card_game_candidates.build_candidate`。CPU 检查覆盖规则、合成物理证据与 HTTP 生命周期；本次接入的原生 HTTP 验证按任务单独封存。物物滑动、盘盘碰撞和停止探针属于场景开发，不代表完整机器人滑盘对局；开发报告不进入运行依赖。
