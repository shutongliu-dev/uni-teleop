# 实验室公开规则与私有裁判

统一入口为 `rules.public_rules(task_id)`，当前作者使用 `laboratory_rules.v2`，冻结到每个新发布的 `rules.json`。旧发布保留自身 v1 规则。`NativeTaskObserver` 在每个原生物理子步读取完整物体状态和带符号接触，`SequenceEvaluator` 在 20 ms 控制观察时读取其摘要。裁判不接收 simulator handle，不控制机械臂或改写物体状态。

所有任务允许台面上的纠错、重抓和重新放置。完成需真实支撑、机器人释放和共同持续 300 ms 稳定。器具稳定使用每子步滑动的 20 ms 位姿变化及 4 mm / 0.10 rad 区间约束；称量颗粒检查竖直位移率 `≤0.03 m/s`、竖直范围 `≤4 mm` 和不变的杯内库存，允许不影响称量的横滚，不以球的朝向作为条件。初始化只建立基线，初态和独立展示姿态都不自动得分。缺失、不连续或不一致的证据记未知；物理异常、任务失败、预算耗尽和取消分别记录。

1. **样本分类**：四瓶按可见颜色全部进入对应托盘，直立并实际受托盘支撑。允许错放后改正。
2. **试管入架**：三支试管各占一个不同空孔，基本竖直，管底在架底受支撑。试管身份不作限制，不要求不可见的编号配对。
3. **开盖复盖**：瓶身进入真实防转座；独立盖沿螺旋结构转出、抬离，在盖托释放放稳；重新旋回后把瓶子送回岛台。裁判保留顺序历史，复盖需瓶盖相对位置、方向和瓶口支撑证据。
4. **颗粒称量**：称量舟放在后台平台，药匙装载颗粒并输送进舟。杯内为 `6±0.6 g`，累计洒落不超过 `1 g`，药匙归位。只有曾由药匙承载、实际位于舟内的颗粒参与任务完成；舟直立、平台支撑且卸除机器人/药匙托举后才能确认读数。24 个颗粒 ID 完整记账，飞行中先记待定，稳定落到器具外或地面后累计为洒落，捡回不减累计量。任务平台的顶面及前侧数字屏以 `g` 显示净颗粒质量：自动扣除 **28 g 空舟**，空舟稳定后显示 `00.0`，12 颗显示 `06.0`。同组颗粒、舟支撑和释放稳定满 300 ms 才出数；无舟、移走、手或药匙托举、颗粒变化、竖向不稳定或证据故障时立即显示 `---`。读数独立于目标达成、药匙归位和舀取历史，方便补料；屏幕显示目标数值不等于任务成功。屏幕只改非碰撞几何的显示材质，质量来自名义颗粒库存，不是测力传感器或机器人持物负载。
5. **移液分装**：活塞抽拉且吸嘴实际浸没才吸水；压杆排水，空吸不造水。两杯各 `8–12 mL`，累计洒漏不超过 `2 mL`，待落水量不超过 `0.5 mL`，工具归架放稳。源杯、工具、两杯、飞行水和累计洒漏总量必须与初始 `80 mL` 相符。水量模型使用实际原生活塞行程与杯口位姿，不读取目标水量控制流动。

`get_task.public_rules.object_properties` 公开每个动态任务物品的 ID、中文名称、`nominal_mass_kg` 和质量含义。分类瓶各 25 g；试管各 20 g；瓶身 90 g、独立盖 25 g；空舟 28 g、空药匙 26 g、每颗颗粒 0.5 g；空供液杯 120 g、空接收杯各 60 g、移液筒身 65 g、独立活塞 16 g。这些是冻结资产的模拟质量，逐件与元数据核对，不是当前负载读数。Task5 的有限体积水量没有原生水重反馈，不能把这些空载质量描述成装水总质量。旧任务未声明该字段时，通用公开合同完全省略它，保留原有合同哈希。

公开任务 API 提供上述静态属性、规则、预算和粗粒度阶段；Task4 实时克数通过公开 RGB-D 中可见的任务平台屏幕观察。裁判使用的原生位姿、接触及逐颗物料账本仍保存在私有证据，不作为 Agent 控制接口。任务之外的桌面陈设是固定背景，不是可抓物品、目标区或得分支撑物；不能借背景架具替代任务规定的托盘、架孔或称量平台。工程物物探针只验证其明示的动作边界，不能代替数采的抓取、整段轨迹或完整任务成功。
