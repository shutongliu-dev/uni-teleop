# 机械五任务：公开规则与裁判说明

新增 Task6–9 的去重设计与独立裁判见 [NIST 任务说明](NIST_TASKS.md)，公开规则实现为 `nist_rules.py`，冻结时一并绑定原生观测器和评分器。本文下面保留原 Task1–5 的规则与历史说明，新增任务不改写这些旧发布。

五项任务都由单 FR3＋右 SHARPA W01 通过正常机器人动作完成。裁判检查真实零件的摆放、承托、接触传动和松手稳定；动作执行完毕、画面看起来到位或进度接近完成，都不能代替成功判决。

本文解释当前源码中的规则。每次运行以该任务冻结的 `rules.json`、`task.json.public_rules` 和对应裁判源码为准；历史发布不会自动获得新版规则。规则版本、阈值和裁判源文件必须一起绑定。**L1–L4 是已实现的场景候选；L5 仍为 `planned`。CPU 裁判测试通过不代表物理可行性、机器人任务成功或 L5 原生验收通过。** 当前发布身份由任务目录维护，本文不指定或替换发布路径。

2026-10-20 的 L4 默认选择为 `loose_bolt_candidate_v10_pgs`（manifest SHA256 `47e574e81558ab16e7fffcda9846f2ab8c281660b0c85bb9ee507b95c94f262d`），从独立桌面螺栓／工具供料开始，仍为 `prepared_unvalidated`。v10 保留 v9 的阶段性接触规则、`loose_bolt_v5` 供料窝、reset、工具托、螺纹资产、0.5 ms 步长、共享控制和物理／评分阈值，仅显式将场景求解器设为 PGS；全局 TGS 默认不变。目录与冻结文件是实际身份依据；旧预插入、v7、v8、v9 发布及证据不会被改写。

历史 v8 的 HTTP smoke（开发存储 `datasets/fr3_sharpa_bench/development/mechanical_l4_loose_default_20261020/l4_http01/qualification.json`） 在首 20 ms 因螺栓供料窝误带工具侧轨而触发 `safety_stop/reported_penetration_bound`，最大报告穿透约 3.009 mm，`physics_valid=false`；reset 的几何交叠约 2.5 mm。该失败不因 v9 的供料修复被改写，v9 也不能继承旧发布的初始化或操控资格。

## 共同规则

- 只控制机器人。允许在规则范围内重抓、对齐、回退和重试；裁判不会自动搬动物体。位姿回放、吸附、焊接抓取或直接向任务物体施加外力不能获得任务成绩。工程诊断台架的加载结果单独记录。
- 初始状态只用来核验本回合身份，不计装配或传动成绩。L4 历史预插入版的预啮合螺纹和预插工具也不计分；当前 loose 版的拾取、起牙和插工具阶段不提前获得旋拧信用。
- 松手依据原生接触流。即使接触冲量为零，只要仍报告机器人与相关零件的接触流，就不满足松手条件。取得承托或传动信用则另需符合相应的正向冲量条件。
- 稳定时间必须连续。成功前被触碰、移动、漂移或其他条件失效会按本任务规则重计稳定窗口，不能拼接多个短暂合格片段。接受成功后，结果锁存，后续观测不会撤销或改写它。
- 放错、未到底、没有取得进度等普通未完成状态不自动判输。动作格式或参数不合法，由公共接口拒绝；拒绝本身不等于任务物理失败。运行器仍可另行记录预算或故障结果。
- 缺失观测或坏接触回执不能被当作“没有接触”。当前回合证据失效后不能跳过缺口继续累计成绩，需要修复证据来源并开始新回合。

新外观／布局候选在每个任务中各放入 **5 件非评分自由散件**（两只螺母、两只垫圈、一只短螺栓）。它们有真实碰撞，但不属于任务目标，不要求将其分类、装配或用其完成传动，也不扩充冻结的评分零件／工具名单。评分目标仍为各节列出的原物体；散件的碰撞可能影响操作，非评分不等于脱离通用物理安全检查。目标浅盘和功能夹具保留，移除的只是多余供料垫块；这一新初态不能沿用旧布局的原生资格。

这些机械任务是单主体操作任务，使用普通 `/episodes`。它们借鉴棋牌室的可恢复裁判原则，但没有双方轮次、落子意图或提交棋步接口。

## 裁判状态与运行结束原因

| 裁判状态 | 含义 | 本回合能否继续 |
|---|---|---|
| `ongoing` | 尚未完成；`phase` 和原因码说明当前需要满足的条件 | 可在预算内按本任务规则继续 |
| `success` | 所有条件和完整稳定窗口通过 | 已接受的终局，结果锁存 |
| `task_failure` | 完整有效证据确认违反任务明示的不可恢复规则 | 终局；当前五任务中主要对应 L4 的螺纹／禁止接触边界 |
| `evaluator_invalid` | 观测数值、初态、时钟或原生接触证据无效 | 停止本回合且不可评分；不记为正常任务失败 |
| `safety_stop` | 有效物理观测越过冻结的速度或穿透上限 | 停止本回合，单独记录；不作为普通恢复状态继续计分 |

预算耗尽、用户取消、API／仿真故障属于运行器的结束原因，不新增上述裁判状态，也不能伪造成 `task_failure` 或 `success`。预算内未做完应保留“未完成”的事实；证据错误不能被包装成策略失败。取消单个动作不等于取消回合；通过结束回合操作确认取消后，才记录对应的回合结果。

发布新版规则的回合在 `task_requirements` 中分别返回 `referee` 与 `episode={terminal, outcome}`。前者是最后一次已验证的物理裁判状态，后者是运行器的最终回合状态。**最终成绩以 `episode.outcome` 为准**：预算、安全审计或运行故障可以让回合以未完成或异常结束，但不应改写此前接受的物理裁判记录。例如 `referee.state=ongoing` 与 `episode.terminal=true` 可以同时成立，此时不能凭 `referee.recoverable=true` 继续操作已结束回合。

`recoverable=true` 只表示裁判仍处于 `ongoing`，不保证剩余时间足够，也不保证当前物理问题一定可以解决。终局后想重新尝试，须实际重置场景并重新核验初始状态，不能只清裁判计数器后沿用已完成布局。

## L1：零件分拣 `parts_sorting`

将方块、圆柱、圆环分别放入对应浅盘。检查的是完整零件边界在盘内，不能只把中心放进盘里；零件底部还需到达盘底高度，并由指定浅盘实际向上承托。不要求精确居中或指定朝向，也不按搬运先后计分。

三个零件须同时满足正确摆放、指定承托、机器人松手和稳定条件，连续保持 **0.5 秒**。任一件失格，三件共用的稳定时间都会清零。

放错盘、压在盘沿、仍拿在手中或被碰动都可以在同一回合纠正。仅将另外两件放稳不能弥补第三件未完成；分别放稳过三件也不能替代三件同时稳定。

## L2：插销入孔 `peg_insertion`

将两根插销分别放入指定插孔，实际到达孔底并取得夹具承托。停在漏斗导入口、悬在孔中或由手托住都不算完成。两根销的操作先后不限。

两根销须同时满足轴线、底部高度、倾角、指定承托、松手和稳定条件，连续保持 **0.5 秒**。偏斜、未到底或放错孔可以正常拔出、对齐和重插；任一根条件失效都重新开始共同稳定计时。

## L3：轴与隔套装配 `shaft_spacer_assembly`

最终从下到上必须为 **垫套 → 宽环 → 顶环**，承托链为 **夹具肩台 → 垫套 → 宽环 → 顶环**。仅有正确的外观或高度不够，每一层必须从指定下层取得实际向上承托。

裁判检查最终层序，不把操作时序当成不可撤销的逻辑步骤。可以先拿起任意零件；装错层序后也可以拆下重装。三件须同时满足轴线、底部高度、倾角、承托、松手和稳定条件，连续保持 **0.5 秒**。任一件未合格，所有零件的共同稳定窗口重计。

### L1–L3 的阶段与稳定含义

| 阶段码 | 中文含义 | 常见原因码 |
|---|---|---|
| `not_started` / `reset` | 等待或核验初始状态，不计分 | `not_sampled`、`reset_baseline_not_scored` |
| `placement` | 摆放或装配未到位 | `outside_matching_tray`、`not_at_tray_floor`、`axis_offset`、`bottom_height`、`axis_tilt` |
| `support` | 尚缺指定承托 | `required_support_missing` |
| `release` | 仍需松手 | `robot_contact_present` |
| `settling` | 等待完整共同稳定窗口 | `still_moving`、`previous_endpoint_not_ready`、`stability_drift`、`stability_window_incomplete` |
| `complete` / `invalid` / `safety_stop` | 成功、证据不可用或安全停止 | 对应终局原因 |

稳定窗口要求每个 20 ms 区间的前后端点几何与速度均符合要求；刚到位或刚停止运动的上一段不补计。累计位置／方向漂移相对于首个计时间隔的前端点，而非逐帧更换参考或仅检查相邻帧差值。

| 当前冻结条件摘要 | L1 | L2 | L3 |
|---|---|---|---|
| 目标几何 | 完整零件在正确盘内，最低点距盘底误差 ≤ 0.5 mm | 轴偏移 ≤ 3.25 mm，底高误差 ≤ 0.5 mm，倾角 ≤ 10° | 轴偏移 ≤ 4.25 mm，底高误差 ≤ 0.5 mm，倾角 ≤ 5° |
| 共同稳定时间 | 0.5 s | 0.5 s | 0.5 s |
| 稳定线速／角速上限 | 5 mm/s、0.05 rad/s | 同左 | 同左 |
| 稳定锚点位置／方向漂移 | 0.2 mm、0.01 rad | 同左 | 同左 |

各完整 20 ms 窗口都要有指定支撑在受支撑物体上的净向上法向冲量；向下冲量不能取绝对值变成承托。接触可以脉冲出现，不要求每个子步都存在静态支撑接触。

## L4：散装螺栓装配 `fastener_assembly`

当前默认从独立桌面供料托拾取螺栓，对准导向口并起牙，再将独立、受重力的工具接合六角孔。loose v10 在建立稳定基线前允许手部直接接触螺栓完成这些操作，但不授予旋拧信用；机器人接触会阻止被动稳定计时。螺丝与夹具、工具形成有效接触并在无机器人接触下连续稳定 **0.5 秒**后，裁判才记录旋拧基线。之后握住工具，从夹具正 Z 轴上方向下看，沿顺时针额外旋入约 **30°**，对应名义额外下行 **0.250 mm**。冻结目标允许最终转角 **25–33°**，有效接触支持的净转角至少为 **25°**；下行量也须达到该下限对应的推进。历史预插入版从已啮合／已插刀状态开始，原规则及证据保留。

正向进度必须来自同一原生子步内的 **手—工具、工具—螺丝、螺丝—夹具** 接触链，且至少覆盖该 20 ms 窗口的一半子步。螺丝的实际转角和轴向下行需符合 **3 mm/圈** 导程；当前 30° 规则的导程残差上限为 **0.05 mm**，合格链累计接触时间至少 **0.1 秒**。这些是既有任务条件，不能与 L5 的 SDF 诊断误差混为一谈。

没有完整接触链的正向微动不增加信用；所有反向运动都扣除信用，无论反转时是否仍有工具接触。信用不超过实际保留的净转角，不能反复进退刷分。达到目标后，机器人须离开螺丝和工具，二者连续稳定 **0.5 秒**；工具可以留在螺丝中，工具—螺丝和螺丝—夹具的有效接触条件仍需满足。

| 阶段码 | 需要完成的事情 | 可恢复情况 |
|---|---|---|
| `settle` | 无机器人接触的被动稳定，建立基线 | 被触碰或移动后重新计时 |
| `advance` | 通过工具旋拧，保留足够实际推进与接触信用 | 重抓、短暂无信用微动、工具重新接合、反转后重新推进；超过目标区但未越过硬边界时可回转纠正 |
| `release` | 松手并完成全新的 0.5 秒稳定窗口 | 零冲量接触、运动或漂移都清零此窗口，纠正后重计 |
| `complete` / `stopped` | 成功或本次评估已终止 | 终局后不能继续改写结果 |

可恢复原因包括 `uncredited_motion`、`reverse_motion_debits_credit`、`target_turn_exceeded_recoverably`、`tool_reengagement_required`、`robot_contact_prevents_release` 和稳定窗口重计原因。重抓不自动清除此前有效净信用，但反转仍会扣回。

下列有效证据会触发 `task_failure`，不能在同一回合恢复计分：

- 超过公开 `minimum_pair_impulse_ns` 门槛的非手部机器人接触螺丝或工具，或基线建立后的机器人直接接触螺丝。当前门槛为 `1e-8 N·s`；松手条件不会因此忽略零冲量接触。loose v10 沿用 v9/v8 的基线前手部拾取许可；旧 preinserted 禁止直接接触螺丝，历史 loose v7 没有拾取豁免，其冲突不改写为通过。
- 首次同时出现螺丝—夹具与工具—螺丝接触的啮合窗口起，螺丝偏离允许螺纹轴线或倾角：轴偏移超过 **1.5 mm** 或倾角超过 **5°**。这早于稳定基线建立；桌面供料初态不按已啮合轴线判失败。
- 基线建立后，螺丝与夹具的有效支撑连续缺失超过 **1 ms**。
- 导程残差超限，或基线后的累计净转角绝对值超过整次操作上限 **90°**。超出最终 33° 目标区与超出 90° 硬边界是两种不同结果。

速度和穿透越界属于 `safety_stop`；坏回执、NaN、时钟不连续等属于 `evaluator_invalid`。两者都不与上述有效任务失败混淆。完整原始条件见 [L4 规则](tasks/fastener_assembly/rules.py)和[裁判](tasks/fastener_assembly/evaluator.py)。

## L5：齿轮装配与传动 `gear_train_assembly`

本节说明已实现的裁判候选，**不开放仍为 `planned` 的任务，也不代表齿轮物理已通过**。

当前 v3 规则对应共享 `gear_train_assembly/v3_4`：输入／中间／输出齿数为 **20/32/20**，相邻轴距 **130 mm**，中间轮外径 **170 mm**。中间轮按原 5 mm 模数增齿；正常孔轴、齿侧和套筒配合空程保留，**空程本身不是故障**。CPU 工具扫掠和供料布局只覆盖已声明的竖直居中工具与桌面位置，不构成手部无碰撞或任务成功条件。原等齿数版的发布和实测保持原规则，不自动换算成新版成绩。

先把三个齿轮装在指定轴上，各自取得工作台承托。松开齿轮并稳定 **0.3 秒**后，建立本段传动的零转角基线。自行选择工具从输入端驱动；工具名称不决定得分。持握须由两个不同右手连杆提供相对法向载荷，再经过工具与输入齿轮、两处真实齿轮啮合及各齿轮承托组成完整接触链。

正向信用要求同一子步内完整链成立，覆盖至少一半原生子步，且传动角速不超过 **15°/s**。从世界正 Z 轴上方向下看，输入与输出逆时针、惰轮反向；理论中间轮／输入轮转角比为 **−0.625**，输出轮／输入轮为 **+1**，最终实际比例相对理论值的误差不超过 **5%**。裁判将中间轮真实转角乘以 **32/20** 换算成输入等效角后检查信用与相位；整个基线段的成对相位误差从未超过 **2°**，原数值阈值没有放宽。原始记录仍保留各轮真实转角。输出净转角须为 **25–35°**，接触信用至少 **25°**，合格正向工具传动累计至少 **0.1 秒**。

最后机器人须松开全部齿轮和所有工具。三个齿轮与本基线段所有曾获得正向信用的工具一起稳定 **0.3 秒**；工具可留在接合位置。换工具不能让先前参与传动的工具逃过最终稳定检查；未参与得分的工具不新增末窗稳定要求，但机器人仍须松开它。

| 阶段码 | 条件与恢复方法 |
|---|---|
| `assembly` | 调整就座、对齿或重放；未就座和直接接触齿轮会清空传动基线及信用 |
| `assembly_settling` | 三齿轮就座、承托、松手后累计 0.3 秒；扰动后重计 |
| `transmission` | 从工具输入端传动；缺链或超过传动计分速度的窗口不加正向信用，所有反转仍扣信用 |
| `reassembly_required` | 按齿数换算的输入等效相位历史曾超过 2°；需要通过实际离座重装或直接接触齿轮，触发整段基线清空，再松手稳定重建 |
| `release_settling` | 达到转角、比例和信用条件后松手稳定；运动、漂移或接触中断此窗口后重计 |
| `complete` / `unavailable` / `safety_stop` | 成功、证据不可用或安全停止 |

机器人直接接触任意齿轮，或工具接触惰轮／输出轮，会触发 `direct_drive_requires_reassembly`，不能借此获得原传动段信用。重建会同时清空转角、信用、最大相位历史、交互与稳定计时以及已使用工具集合；仅修正最终角度不会洗掉此前超限的相位历史。`phase_error_requires_reassembly` 因而表示仍可按规则重建，不是自动判输。

当前就座条件为轴偏移 ≤ **0.4 mm**、底高误差 ≤ **0.3 mm**、倾角 ≤ **0.5°**。当前稳定要求包括线速 ≤ **2 mm/s**、原生角速 ≤ **0.05 rad/s**、20 ms 位姿差分角速 ≤ **0.02 rad/s**，以及相对窗口锚点位置漂移 ≤ **0.1 mm**、方向漂移 ≤ **0.5°**。超过 15°/s 的传动计分界限与越过对象安全上限须分别处理：前者可以是 `ongoing`，后者为 `safety_stop`。完整规则见 [L5 规则](tasks/gear_train_assembly/rules.py)和[裁判](tasks/gear_train_assembly/evaluator.py)。

## 公开信息与私有证据

启动服务时选择目录绑定的新发布，然后沿用已有接口：

- `GET /tasks`：静态中文规则、阶段／原因字典和规则哈希。
- `POST /episodes`：创建响应中的 `task` 携带同一规则，以及初始 `referee` 和 `episode` 状态。
- `GET /episodes/{id}/task`：取得当前粗粒度裁判与回合状态；本地入口为 `session.task_requirements()`。普通 observation 不重复携带这份任务合同。
- `GET /episodes/{id}/result`：读取最终回合结果。查询规则不会执行动作、重置裁判或增加传动信用。

新合同还提供公共只读函数 `get_task`，参数为 `{}`。现有 FunctionSession 可以从能力目录发现并调用它，将最新阶段、原因码和回合结果交给模型；它不推进仿真或消耗动作次数，仍受客户端查询预算约束。创建响应中的初始任务状态不会自动刷新，决策应以最近一次 `get_task` 结果为准。未选择该合同的旧任务将此函数标记为不可用，原接口保留；客户端与服务需使用包含该函数的同版协议，旧冻结客户端不会自动升级。

公开响应的 `public_rules` 是完整规则中经过白名单校验的 `referee` 子合同；其 `public_rules_sha256` 校验这份实际返回值。冻结 `task.json.public_rules_sha256` 则校验完整 `rules.json` 对象，`public_referee_contract_sha256` 单独绑定子合同。规范哈希使用键排序、紧凑分隔符、`ensure_ascii=True`，禁止 NaN；文件字节哈希另由 release manifest 绑定。新旧版本分别保留，不对旧发布补写合同。

静态公开契约 `physical_task_referee_contract.v1` 提供中文指令、阶段与原因码字典、成功条件、恢复方法、结果语义及冻结阈值。动态粗状态 `physical_task_referee_state.v1` 仅包括：

```json
{
  "schema": "physical_task_referee_state.v1",
  "state": "ongoing",
  "phase": "release",
  "reason_codes": ["robot_contact_prevents_release"],
  "terminal": false,
  "recoverable": true
}
```

上例是 L4 的静态示意，不是运行观测。每个 `phase` 和 `reason_codes` 都必须属于该任务冻结的字典；不把内部异常文本当作公开原因。

精确物体位姿、目标误差、接触冲量、逐对象计算结果、转角信用、精确计时和原始裁判日志保持私有。公开的是规则阈值和粗状态，不是当前物理真值。公共 RGB-D、机器人反馈等沿既有接口提供，不因新增规则自动暴露内部观测。公共投影与校验实现见 [通用协议](../../../bench/protocol/task_referee.py)，场景侧契约见 [referee.py](referee.py)。

裁判使用完整连续的 **20 ms** 物体位姿／速度观测，以及覆盖区间内全部 **0.5 ms** 原生子步的法向接触回执；这不等于连续子步物体轨迹，也不声称测得真实扭矩。缺失、重复、越时或数值无效的证据不能补成零值。规则哈希、实际加载的冻结裁判和观测有效性是不同的检查，缺一不可。

## 验证范围与 L5 几何诊断的区别

CPU 正负例与恢复测试证明的是裁判在给定证据上的行为，包括不能以零冲量假松手、不能把坏证据记为有效失败、不能拼接稳定片段或清掉坏历史保留好信用。它们不证明碰撞、螺纹、齿面传动或实际机器人抓握已经合格。初始化承托、工程外载诊断和公开机器人整任务也各有独立证据范围。

L5 几何排查中讨论的 **约 47 µm** 是特定 SDF 查询的误差观测，**不是新增任务门槛，也不是用户确认的装配公差**。相关探针使用的 **20 µm 投影距离**与 **1 µm 零残差**是该诊断的严格检查条件，不会自动写入任务成功判据。诊断未通过不能单凭这一点断言实际装配一定不可能；反过来，也不能因为误差看来较小就宣称齿轮碰撞和传动已经验收。现有失败及限制继续保留，L5 的 `planned` 状态和物理资格必须由独立原生证据处理。
