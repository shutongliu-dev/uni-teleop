# 厨房六项任务

六项任务共 **35 个独立动态物体**，覆盖载物端送、果蔬分拣、薄餐具收纳、锅盖配合、瓶罐与包装食品归位、餐后器具整理。每个任务还加载 **12 件固定背景物品**：果酱、蜂蜜、油壶、盐磨、胡椒磨、咖啡罐、可可罐、香草罐、面粉盒、茶盒、折叠餐巾和蛋杯。它们有明确身份及碰撞，公开说明为非评分陈设，不冒充可操作物品。

沿用住宅厨房 `kitchen_galley_20261019_v2` 的柜体、电器、锅具、搁板、推车、植物和原开源扫描陈设。每项独立加载动态物品、必要夹具和附加陈设，不改写父环境。原始 FR3 + 右 SHARPA、组合版本、控制器与物理材料保持原配置。

## 物品、布局和物理约定

原创 CC0 米制网格保留可用杯腔、碗腔、盘面、锅腔与开口把手，不用实心凸包封住容器。新瓶罐有不同肩颈、旋盖纹、标签色带和封边；纸盒有折顶与封口；罐头有卷边、拉环；大小盘、深浅碗、直筒杯和矮口茶杯具有不同形状。原托盘铆钉、面包芝麻与刻纹、果蔬蒂叶与根纹、勺面和叉齿继续保留。

可动物品均为独立被动刚体，质量、质心、惯量、碰撞和源／目标支撑写入资产元数据。瓶罐内容物密封并计入整体质量；不模拟液体、开盖、加热、切割、洗涤或食物变形。质量与摩擦为公开工程先验，未声称实物标定。图案细节允许只参与渲染，承托和容纳使用真实碰撞几何。

任务1、2、3、5、6使用吧台，机器人偏航−90°；任务4使用备菜台与冷灶，偏航+90°。基座固定在 `(.65, 0, .78)m`，原29关节待命状态不变。附加陈设在吧台外侧边缘，与中央保护工作区留有间隙；它们不作为评分容器或隐藏支撑。种子保留在合同中，当前初态是冻结合法供料布局，不暗中随机改变几何。

Task5目标盒通过深蓝、奶白、木色区分；Task6通过大奶白盘、蓝色杯盘、木质餐具盘区分。目标元数据给出对象说明、类别和目的地；实际Agent接口通过公开裁判指令说明可见目标，不暴露真值位姿、接触图或目标示例位姿。

## 规则与裁判

详细合同见[RULES.md](RULES.md)及各任务README。六项共用完整原生子步证据、真实承托、全部松手和共同稳定0.4秒。稳定速度使用每个0.5ms子步滚动的20ms位姿窗口，同时检查4mm／0.08rad稳定包络，接受小幅正常接触抖动。打开手指的命令本身不能替代松手证据。

- 早餐先在源区释放配盘0.3秒，再实际离台15mm、带载净移动0.50m；空盘先到终点再拼装不算端送。
- 锅先在指定冷炉位释放稳定0.3秒，再盖独立盖；锅中心允许35mm、盖偏心12mm，不规定耳柄转角。
- 分类任务按整个碰撞外形是否容纳及实际支撑判断，不按精确点位打分。
- 新任务允许有根、无环的同区域支撑链，盘碗可真实堆叠；类别错误、悬空、骑边或机器人扶住不能通过。
- 错放、重抓、扶正和安全台面恢复允许重试。Task5/6提供240秒仿真预算，原四项120秒，公开动作上限6000；超时／取消为未完成，证据缺失为unknown，落地和物理安全停止分别记录。

初态仅建立基准，不给完成信用。裁判只读模拟器证据，不驱动物体，不附带任务专用抓取策略。

## Bench与Agent入口

六项均为普通 `/episodes`，共用现有公共函数。先启动与所选任务冻结release一致的bench，再在Agent使用 `--family kitchen --task task1` 至 `task6`，或上表的canonical ID。任务5、6应显式给Agent `--sim-budget none`；这会取消客户端的额外时限，由冻结裁判执行240秒任务时限；全局CLI默认预算仍为120秒，具体参数见[Agent入口](../../../agent/model_client/README.md)。

```bash
# 示例：Task5；替换为实际部署所用服务参数
BENCH_TASK_RELEASE=<开发存储>/datasets/fr3_sharpa_bench/isaacsim/releases/kitchen/pantry_stocking/v2 \
  .venv/bin/python -m uvicorn bench.runtime.server:app --host 127.0.0.1 --port 8000

# 查看某项冻结任务定义／供上层启动器选择
.venv/bin/python -m agent.model_client.scene_tasks --family kitchen
```

Agent家庭选择校验目录冻结发布；服务实例绑定一个release，不会因为改task参数就隐式切换场景。公开规则、初始化、资源哈希和只读裁判一起冻结；任务5/6使用v3规则，原四项保留v2规则。旧发布继续可加载。
