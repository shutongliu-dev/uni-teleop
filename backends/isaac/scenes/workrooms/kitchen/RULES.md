# 厨房任务与裁判

规则由 `rules.py` 公开，`evaluation.py` 的只读 `NativeTaskObserver` 逐个原生物理子步采样，`SequenceEvaluator` 按正常控制周期接收私有摘要。规则、资产元数据和裁判代码一同冻结；源房间 `/World/Geometry/` 支撑路径只在 observer 中明确映射为组合后的 `/World/Room/Geometry/`，不改写原资产。

| 任务 | 核心完成条件 | 允许的误差和恢复 |
| --- | --- | --- |
| 早餐配盘与整盘端送 | 源区配齐盘、空杯、两块面包，释放稳定 0.3 秒；带载离台至少 15 毫米，水平净端送至少 0.5 米；目标区域放稳 0.4 秒 | 使用整个标记区域，无指定杯柄朝向或精确摆盘点；允许被动小滑动、60 毫秒内接触微振动；中途安全落台、重新扶载荷后回源区重试 |
| 果蔬分拣 | 三个番茄与三根短胡萝卜进入各自浅盘，实际落在盘底，全部松手稳定 0.4 秒 | 无摆放点和朝向要求；允许果蔬互相接触和台面滚动后回收；错盘可取回 |
| 餐具收纳 | 六件餐具进入对应类别格，有真实支撑链，全部松手稳定 0.4 秒 | 柄朝两端均可；同类可并排或轻微搭叠（离格底不超过 18 毫米），不能骑隔板、跨格或仅靠其他类别物体支撑 |
| 放锅盖盖 | 锅先放稳在冷炉位，再放独立盖子；最终全部松手稳定 0.4 秒 | 锅中心范围 35 毫米，锅倾角 10°；盖允许 12 毫米偏心、8°相对倾角、8 毫米座高误差；不要求锅耳和盖旋转角精确对齐 |
| 食品归位 `pantry_stocking` | 八件密封食品按油醋瓶、调味品、干货三组放入对应盒，真实承托、全部松手稳定 0.4 秒 | 无指定槽位、标签朝向或摆放顺序；瓶罐基本直立，密封纸盒与罐头可平放；同盒物品可真实堆放，错盒可取回 |
| 餐后收台 `table_clearing` | 四件碗盘、两件杯具、两件叉勺收进三类接收盘，真实承托、全部松手稳定 0.4 秒 | 碗盘开口朝上、杯具基本直立；允许任意合理顺序的叠盘、套放、并排和叉勺搭叠，不要求使用示范目标位姿 |

食品归位的公开清单是：橄榄油瓶 `olive_oil`、醋瓶 `vinegar` → 油醋瓶盒 `bottles_bin`；盐罐 `salt`、胡椒罐 `pepper`、红椒粉罐 `paprika` → 调味品盒 `seasonings_bin`；米盒 `rice_carton`、意面盒 `pasta_carton`、番茄罐头 `tomato_can` → 干货盒 `dry_goods_bin`。前两组保持不超过 15° 的基本直立，干货组朝向自由。包装保持密封，不要求开盖、倒料或精确标签朝向。

餐后收台的公开清单是：大餐盘 `dinner_plate`、小餐盘 `side_plate`、麦片碗 `cereal_bowl`、小碗 `small_bowl` → 碗盘盘 `dishes_tray`；马克杯 `mug`、茶杯 `tea_cup` → 杯具盘 `drinkware_tray`；勺 `spoon`、叉 `fork` → 餐具盘 `cutlery_tray`。碗盘与杯具保持不超过 15° 的基本直立；杯柄、叉勺朝向自由。无需洗涤、模拟污渍判断或强制叠盘顺序。

两项新任务均按完整碰撞外形判断是否在接收盒/盘内，边界容差 2 毫米。真实支撑可直接来自对应盘底，也可经过同一接收盘内的其他计分物体；裁判从有盘底支撑的物体开始逐层扩展支撑链，因此浮空环、外部陈设、错误类别物体或相邻盒不能制造支撑。套放碗盘时允许上层底部低于下层盘沿，以实际几何和向上接触为准，不另设精密叠高限制。每件物体都需离开初始位至少 20 毫米，整个任务共用连续释放窗口，不能把不同时刻分别放稳的记录拼成完成。元数据中的 `goals.body_poses_xyzw` 是几何与承托检查用的示范布局，不是精确评分位姿。

丰富厨房背景中的固定食品包装、调味瓶、清洁用品、器皿等属于非计分陈设。只有每项规则明确列出的动态任务物体计分，既不要求整理额外陈设，也不允许靠它们托住目标物体来完成。固定陈设不混入动态 `actors` 清单。原有四项仍使用原始任务物品及 `kitchen_rules.v2`；两项新任务使用 `kitchen_rules.v3`，冻结历史发布版保留原裁判。

末端共同稳定窗口允许最大线速 25 毫米/秒、角速 0.25 弧度/秒。速度由相隔 20 毫秒的真实位姿计算，窗口在**每个原生子步**向前滑动，不仅在 20 毫秒控制观察点采样；不足完整窗口时不计稳定。连续稳定段仍逐原生子步限制相对段首的位置漂移 4 毫米、转角漂移 0.08 弧度，因此控制观察点之间的大幅往返也会重新计时。求解器瞬时 tensor 速度脉冲保留为诊断，不单独当作真实宏观运动。所有任务的配盘确认、锅先放稳、最终放稳和私有静置证据使用同一定义。任意机器人接触、目标或支撑失效会重新计时，打开手指命令本身不是释放证据；缺失原生采样仍是无效证据。

支撑同时检查真实原生 actor 对、物体上的向上法向冲量和底面/容器几何。已声明碰撞凸包顶点时使用其完整极值，避免旋转球形果蔬的包围盒虚角误拒；旧测试夹具未提供顶点时才回退到局部界框。侧向接触、向下接触、仅近目标、悬空或骑边均不给完成信用。原生接触的有符号向量不取绝对值、不按碰撞体数量缩放。只在已有向上承载证据、几何仍一致时保留短接触间隙；睡眠物体可保留先前承载记录，但必须位置不变、速度低且无机器人接触。这不是定量力平衡资格。

早餐信用必须来自同一趟真实带载运输。空托盘先搬到终点再配盘、沿台推滑、半路卸载或直接用手托住面包/杯/盘都不能通过。完整原生帧保留阶段事件，失败尝试的旧运输事件不让后来终点拼装得分。允许安全台面重试，不把一次错放永久判负。当前原生摘要没有接触点/具体 collider 身份，因而裁判验证手与托盘 actor 的接触，**不声称验证了手只接触把手**；把手是可用的抓持结构，不是隐含评分门槛。

初始化仅建立无分基准；源状态不自动得分。缺失采样、错时钟、错误 reset、缺失冲量向量或不匹配配置统一输出 `status=unknown` / `evidence_status=unknown`，不推断物理失败。原有四项声明 120 秒、新两项声明 240 秒的仿真时长；动作上限为 6000，运行器可另声明更短预算。预算耗尽通过通用回合封装返回 `status=incomplete, terminal=true, reason=budget_exhausted` 并锁定结果，不会把同一观察点的迟到完成计为成功；公开物理裁判仍表示任务未完成。取消也不制造任务失败。只有物体落地或离开声明的恢复区域才是任务失败；超出声明穿透限值的物理停止独立记录。公开 `referee` 只包含中文静态规则和粗粒度阶段/原因码，不向 Agent 泄露精确真值。

CPU 正反例仅验证裁判逻辑。原生初始化、支撑、接触机制、机器人触达、实际抓放和完整端送分别需要各自绑定资产与源码的证据；本规则实现不代替这些验证，也不改变机器人控制器。
