# 主从臂 + MANUS 遥操

MANUS SDK独占接收器。由遥操启动的SDK子进程绑定Linux父进程生命周期，
即使Isaac原生退出跳过Python清理，SDK也随之退出，避免残留进程占用接收器。

## Start 直接接管与主臂重力补偿

FACTR 入口默认保存固定七轴对应关系。点击 Start 后，仿真以原关节速度上限
向主臂当前七轴目标运动，接近并稳定后继续一一跟随；Pause 保持。无需点击
额外的读取/对齐按钮，也不要求用户把主臂摆到仿真姿态。接管过程通过正常
物理步执行，不复位物体、不调用腕部IK、不改零位。越界或过期输入仍保持。
旧的显式复位参数 `--align-from-leader` 保留兼容，日常启动无需传入。

非评分练习可加 `--leader-practice-follow`：保留固定零位、方向和逐关节映射，
只将越界轴目标限制在原URDF边界，其余轴继续跟随。角度选取最接近上一目标的
整圈表示，避免在不可达角度区间内来回切换限位端点。转回范围内直接跟随；
仿真消费帧间位移超过0.35rad不再锁停，始终按原关节目标速率限制追赶。
取消接管前稳定停留要求。过期／无效数据、设备或流切换仍保持，须显式恢复。
范围内一一对应，饱和时不声称完整复现主臂。仅改变仿真目标生成，实体电流、
速度及通信保护不变；物理碰撞和接触检查不变。默认严格模式保留。

主从面板：**开始 / 恢复跟随**直接请求跟随与托举；**暂停**保持仿真并关闭托举；
**重置场景**将物体和仿真机械臂恢复初态并暂停；**开启 / 恢复托举**只恢复实体
托举，不改变仿真目标或场景；**关闭托举**只关闭实体输出。主从模式不显示
仅用于视角回中的Recenter。使用系统fontconfig选择中文字体，状态分别说明
仿真限位、手套输入和实体托举。主臂故障保留前16次速度读数，供区分真实高速
与读数跳变；不因界面显示原因相同而自动恢复实体输出。

`--leader-feedback --leader-gravity-urdf <主臂URDF>` 选择主臂重力加阻尼，
替换之前的主从误差弹簧。读取URDF每段质量、重心与关节轴，通过各段重力
对关节的力矩求和计算托举电流；使用主臂模型，独立于仿真Franka的质量。
Start直接请求主臂支持，从已核对的固定校准与实时主臂读数开始零电流使能、
缓升输出；不再等待仿真关节接管。仿真同时按原速度限制追上主臂，仍保留
自身的限位与跳变保持。Pause、主臂失联、终止取消输出。
重力控制线程按主臂串口采样自行计算；100ms输入新鲜度检查使用主臂采样
时间，不使用仿真帧时间。渲染或仿真暂时停止刷新时，只要主臂控制线程与
串口仍正常，重力支持持续。Pause、Reset、Recenter、任务终止、真实主臂
输入超时、速度越界和退出仍撤销输出，不自动重新使能。仿真侧限位、尚未
对齐或降采样后的大关节增量不撤销独立的主臂重力支持；物理线程自己检查
每次编码器读数与速度。反馈按钮可单独请求重力支持。虚拟主从阻力模式
依赖从臂状态，其100ms仿真反馈新鲜度要求保持不变。日志分别记录重力模型
所需电流、输出电流指令与上限；输出指令不是实测电流或已验证的悬停力矩。
FACTR上游电流换算是XC330每Nm1158.73mA、XM430每Nm1000mA；上游driver
实际上写的是原始寄存器值，XM430的`1000/2.69`不能再次作为mA使用。
这些换算仍为上游先验，未测定本机电流—力矩曲线。

此硬件路径要求已有实测关节校准；临时匹配姿态不能证明物理零位。当前
重力模式的串口采集、模型计算和电流输出在独立的 Linux spawn 进程中运行，
不与 Isaac 的渲染／物理 Python GIL 共享；仿真仅发送 Start/Pause 和接收状态。
状态发送另用线程，界面消费阻塞不会阻塞串口控制或 Pause 命令。
父进程退出触发 SIGTERM，子进程清零／关闭输出；若无法清理，硬件看门狗兜底。
Start 命令延迟超过150ms会拒绝，不重放过期使能。局部100ms读数／控制周期、
3rad/s速度界限及硬件100ms看门狗保持不变；周期／速度停机显示实际数值和轴号。
日志新增主臂控制周期及最大周期；进程隔离不代表实时调度或硬件通信不会中断。

默认低电流上限仍为XC33030mA、XM43060mA；操作者核对托举方向后，可显式
设置 `--leader-gravity-current-scale 2` 使用60/120mA第二档，仅作用于重力模式。
两档变化率均为XC33030mA/s、XM43060mA/s，第二档从零到上限需约两秒。
启动读取各电机Current Limit，所选上限超过硬件限制则拒绝；不修改EEPROM。
超限明确报告补偿饱和，因此不能
宣称已能托住主臂。原厂URDF和本机结构、零位、安装方向核实并完成支持
测试后才能确定实际托举参数。重力公式已以解析摆臂
和重力势能数值梯度检查，主臂实际不下垂效果仍待硬件验证。

原生 `scripts.validation.leader_feedback_smoke --follow-on-start` 用偏离
仿真初态的合成输入检查Start自动跟随、原有限速、断流保持和40小步接触。

现场首轮方向测试使用 `scripts.validation.leader_gravity_check --port <稳定串口>
--arm-calibration <已核对的校准文件> --leader-urdf <主臂URDF> --axis 4
--output <新的报告路径> --execute-supported-test`。操作者须全程扶住主臂。
此工具适用于上述七轴FACTR模型与电机组合，先检查静止和零电流，再只让
指定轴按重力模型输出两秒；其余轴目标电流为零，第8轴不使能。保留30/60mA
上限和100ms硬件看门狗，超过50ms输入时效、1rad/s速度或0.15rad位移即退出。
成功或异常后均归零、关闭使能并读回；报告保存逐帧指令、实际电流与退出状态。
通过只说明有限电流输出和关闭链路正常，仍须操作者确认托举方向，不能证明悬停。

## 固定七轴对应与低电流阻力反馈

DYNA/FACTR 路径始终是七关节一对一目标映射，无腕部 IK：
`q_goal[i] = q_robot_ref[i] + sign[i] * (q_leader[i] - q_leader_ref[i])`。
比率为 1；真正执行的目标和实测关节仍受原关节范围、速度、物理接触约束。
不同连杆长度不会变成相同世界位置，方向和匹配姿态必须由操作者实际核对。

旧版 provisional 相对练习模式每次 Start 重新取参考；当前FACTR入口默认固定
校准和Start自动接管，Start/Pause 不改变零位。旧的
`--align-from-leader` 兼容路径可在启动时通过校准读取主臂当前七轴，
复位仿真至该姿态，保持暂停后再按 Start；日常使用无需此参数。
此功能仅用于未评分练习，复位整个场景，后续 Reset 返回此次读取的姿态。
反馈须先关闭，主臂帧独立检查150ms新鲜度、设备身份、八轴完整性和原Franka
限位；失败打印原因，不复位、不夹紧越界角度、不改零位。会话保存原始读数、
七轴目标与校准哈希。Start仍保留七轴0.05rad与250ms稳定接管门槛。
已有校准必须有意义：直接读编码器不能消除错误零位或验证轴向；provisional
文件仍需显式 `--allow-provisional-calibration`，不能称为完成实测标定。

再加 `--leader-feedback` 可运行独占串口的阻力控制线程。启动仍只读取，
必须先 Start 对齐，再按 `Low-force feedback: Enable / Disable` 才允许电机出力。
暂停、仿真对齐主臂、重置、真实输入中断、映射失效、跟随误差超过0.3rad、
主臂速度超过3rad/s、仿真终止或反馈超过100ms均取消反馈，需手动重新开启。
每台电机另设100ms总线看门狗；读取与输出由同一线程拥有，避免只读线程继续
通信掩盖失效的控制线程。退出归零、torque-off并清看门狗；第8轴不使能。

仅加 `--leader-feedback` 而不提供重力URDF时，是**主从角度误差产生的虚拟弹簧与阻尼**，
以电流mA控制，不是实测外力矩还原或重力补偿。从臂受阻、限速或通信延迟
都可能增加阻力。上面的重力模式另需核对本机结构、关节方向和参考姿态。
电流带死区、低通和变化率限制，XC330-T288上限30mA、XM430-W210上限60mA；
这只是首轮低电流试用参数，不是经过测量的牛米标定或硬件安全认证。

可写硬件接口只允许1–7号的RAM地址64（使能）、98（看门狗）、102（目标电流）。
只接受已在current-mode、torque-off、无硬件错误且支持看门狗的1220/1030型号。
先写零电流并逐个读回，再开启输出；不会改变工作模式、EEPROM、位置目标或
触发器第8轴。单位依据 [XC330-T288官方表](https://emanual.robotis.com/docs/en/dxl/x/xc330-t288/)
的1mA和 [XM430-W210官方表](https://emanual.robotis.com/docs/en/dxl/x/xm430-w210/)
的2.69mA，按绝对值向零取整保证不超低电流限额。

`scripts.validation.leader_feedback_smoke` 在原生Isaac用合成七轴输入检查固定
关节跟随、禁止进入IK、只计算不写硬件的阻力方向、限幅和断流归零，以及全部
40接触小步；加 `--align-from-leader` 检查先读取主臂初始化、保持暂停、零位不变，
再以合成 Start 验证跟随。`scripts.validation.leader_haptics_zero --port <稳定串口>
--output <新的报告路径> --execute-zero-current-check` 是需扶住主臂的显式硬件
检查：只以零电流使能，停止通信160ms确认看门狗触发，然后关闭输出；不发送
非零电流或位置目标。CPU串口仿真覆盖零电流读回先于使能、输出限额、触发器
排除，以及仿真失联时即使串口读数继续刷新仍会关闭电机。

本机FTDI低延迟设置由管理员完成。先通过稳定串口确认实际ttyUSB编号，
将对应 `/sys/bus/usb-serial/devices/<ttyUSB>/latency_timer` 设为1ms；不能把
总线掉线简单解释成延迟问题。参考 [FACTR上游部署说明](https://github.com/JasonJZLiu/FACTR_Teleop/blob/main/src/factr_teleop/README.md)。

## 切换 PICO 手柄 + MANUS

现有独立 MANUS 采集与官方优化器也可配合 PICO 腕部控制：PICO 启动器设置
`PICO_TELEOP_ENTRYPOINT=scripts.teleop.master_slave_isaac`，并传 `--arm-source pico`
和下文 MANUS 配置。无需 `--leader-port`、主臂校准或打开主臂串口。
保留 `--mode controllers`、既有视频、工作台与显式 `--arm-home` 参数。
默认暂停，点击 Start；按住右手柄侧握键移动机械臂，松开侧握键可重新摆放手柄，
再次握住时重新建立位置参考。PICO 扳机不驱动手指；MANUS 独立驱动灵巧手。

组合帧保存 PICO 与 MANUS 各自的原始主机时间；任一路超过 150 ms 只保持
对应关节，不拿另一路新鲜数据延长其有效期，映射结束后也检查有效期。
总 Pause/Start 控制两路；PICO 丢失后沿用释放再握紧的恢复逻辑，MANUS 丢失
后 Pause/Start 恢复。控制点仍使用既有 PICO 设置，不启用已撤回的主臂转腕实验。

`scripts.validation.pico_manus_smoke` 复用合成手套与可选官方离线目标样本，
在原生 Isaac 检查腕部、五指运动、分别断流保持和全部 40 接触小步；接受
`--official-fixture`，其他启动参数与原生主从回归相同。合成检查不证明实际
头显链路、手持手柄时的手指可操作性或任务成功。

练习时可传 `--arm-home J1 J2 J3 J4 J5 J6 J7`（弧度）覆盖单臂初始姿态，
例如 `--arm-home -0.3435 0.13963 -0.27925 -2.00383 1.97222 1.69297 -0.62832`。
发布任务需同时指定 `--no-task-scoring`。它只修改本次运行的初始机器人关节，
Reset 继续使用该姿态，不修改发布数据、物品摆位或遥操映射；会话记录显式保存覆盖值。

这是独立于 PICO 和 PICO+MANUS 的第三条遥操方式：

```text
主臂（Dynamixel） -> 校准后的 7D 机械臂关节目标 -> 从臂
MANUS 手套       -> SHARPA 灵巧手重定向
```

主从臂输入通过 `bench.adapters.master_slave` 接口进入。该接口不导入
Dynamixel、从臂 SDK 或 Isaac；硬件 owner 在外层提供 `LeaderState`，并负责
真正的 follower 写入。MANUS 继续复用 `bench.adapters.manus.process_source`
的隔离 producer，不复制 SDK 进程代码。

每个控制 tick 都有两个独立 watchdog：主臂和 MANUS 手部任一超时就只 hold
对应部分。主臂使用保存的固定关节校准：首次逐轴核对方向、匹配参考姿态后，
记录连续 offset；不要使用固定 pi/2 网格猜 offset。日常启动读取已有校准，
可先让仿真复位到主臂当前姿态，稳定后才启用跟随；Start 不重新采集零点。

参考仓库中的重力补偿、夹爪滞回和 dry-run 思路可以复用；其具体 Dynamixel
型号、URDF、端口和控制增益不直接并入 dexbench，必须由本机硬件配置提供。

## FACTR → Isaac 第一阶段（2026-10-23）

当前已实现独立的主臂只读输入和仿真关节跟随入口。最终目标仍是主臂控制
Franka、MANUS 控制 SHARPA；此阶段手部暂用主臂第八轴扳机做联调，MANUS
尚未与这个运行入口联动，不能声称完整主从臂＋手套已跑通。

压缩包只作为参考：不导入其 NUC RPC、主臂力矩、工作模式、重力补偿和旧姿态；
不执行包内程序。采集器仅发 DYNAMIXEL READ/SYNC_READ 指令并独占串口，
读取八个 X-series 电机的 signed position。用户设备实读波特率为 4 Mbps。
机械臂七轴方向只能来自固定校准文件，必须人工逐轴核对，不再默认沿用参考包。
独立主臂扳机模式使用 `--trigger-sign` 设置第八轴方向，不影响七轴校准。
型号表与单位依据 ROBOTIS XC330/XM430 的官方 control table 和 Protocol 2。

从项目根目录启动（先用 `--sandbox --no-video`，避免和已运行的 PICO 视频端口冲突）：

```sh
CUDA_VISIBLE_DEVICES=<GPU-UUID> scripts/teleop/run_master_slave.sh \
  --leader-port /dev/serial/by-id/<实际主臂设备> --leader-baud 4000000 \
  --arm-calibration <本机已测量的固定校准.json> \
  --sandbox --no-video --physics-profile cpu_rigid_v1 --mode controllers
```

默认暂停。Start 请求对齐，机械臂继续保持已确认目标；依照界面的七轴误差，
手动移动主臂，使全部误差 ≤0.05 rad（约 2.9°），且连续 250 ms 内主臂关节
位移 ≤0.02 rad。同时检查与仿真实测姿态和已确认目标的误差，避免实际关节尚未
到位时接管。满足条件的首帧仍保持不动，后续才按固定映射、原有限速跟随。
这些阈值是软件接管默认值，不是实际设备标定精度或硬件安全认证。

数据超过 150 ms、流身份改变、编码器相邻样本跳变
超过 0.35 rad、非有限输入或活动目标越界，都保持已确认目标并要求重新 Start
对齐。等待对齐时，观测间隔超过 150 ms 会重新累计稳定时间；映射越界则
提示手动回到有效范围，不移动仿真机械臂。已启用时不把慢渲染本身当成输入
断流，仍检查本次编码器样本的 150 ms 新鲜度与跳变边界。
Pause、Reset、断流不会改写固定校准。第八轴扳机仍在接管时单独记参考值，
默认 0.8 rad 映射到已有捏合轨迹；MANUS 模式完全不用扳机控制手指。

原生回归工具 `scripts.validation.master_slave_smoke`：220 个控制步，以显式
合成校准和编码器输入验证未对齐保持、稳定对齐、首帧保持、实际关节跟随、
断流保持及重新 Start 不改零点，并验证全部 40 个接触小步。不据此声称真实
主臂方向、重力补偿、抓取或任务成功；实际设备检查保持只读。

MANUS 原生依赖在独立环境配置，禁止装入 Isaac 环境。新增
`bench.adapters.manus.sdk_process --discover-devices` 可读取 Landscape 中的手套
身份，允许不预先猜 glove ID；它不校准、不更新固件、不启用 haptics。
Integrated 按官方 Minimal Client 的主机连接流程运行，但不套用独立 Core 的
版本握手，记录 `integrated-unreported`，不伪造实际版本。外置 Core 保持兼容性检查。

本机联调暂未收到手套骨架：SDK 日志报告设备访问权限错误，以及当前没有
包含 Integrated feature 的 CoreSDK 许可证。USB 识别到接收器不代表手套已配对、
已标定或已获 SDK 权限。可使用合法授权的本地/外置 Core 路径继续联调；
未取得真实帧之前，不猜 glove ID、骨架节点、标定参数或直接复制人体角度。

## FACTR + MANUS 仿真联调入口（2026-10-23）

使用 3.2.0 SDK 及其现有设置。3.2.1 仍为缺省版本，不混用二者的标定设置。

25 节点骨架，按 ChainType/FingerJointType 显式语义转换，不猜数组序号。

### MANUS 手指响应修正（2026-10-23）

真实手套测试显示 MANUS 帧龄约 5–16 ms，物理关节基本跟随目标，但手指目标
沿用了 PICO 的 1 rad/s 软件上限。在约 15 Hz 的现实循环中，每次只推进
20 ms 仿真，造成明显慢动作。MANUS 入口增加 `--manus-finger-speed`，缺省
4 rad/s（仿真时间），逐关节仍取原 URDF 速度和配置值的较小者。PICO 的默认
限速、机械臂限速、原生控制周期、增益、力矩、关节范围及接触检查不变。
这没有提高整条循环的刷新率，也不按现实耗时跳过仿真小步。

`factr_manus_fingertips_v2` 修正 MANUS 的骨段对应：拇指按 CMC→指尖，四指
按 MCP→指尖。原来把四指 Metacarpal→Proximal 的掌骨段也计入手指长度；
实测开放手基准中的缩放约 0.55–0.68，修正后约 0.92–1.37。掌平面也使用
MCP 而非近腕的掌骨起点。这是人体／机器人对应骨段的长度换算，不是额外
统一放大系数。机器人侧仍是有界指尖 IK，不能等同于逐关节人体姿态复制。

回归覆盖掌骨长度不影响手指尺度、同一闭合输入的目标响应改善、原 URDF
范围和速度边界，以及双输入独立 watchdog。改进后的实际手套操作体验仍需
操作者复测；原生合成运动不代表真实抓取或任务成功。

### 单独检查手套

主臂通信不可用时，可显式加 `--manus-hand-only`（仍需全部 MANUS 配置）。
该模式不打开主臂串口，机械臂始终保持已确认目标，只允许右手骨架驱动手指；
界面、输入来源及会话报告标记 hand-only / arm held。它不伪造主臂测量，也
不代表主从臂链路恢复。省略该选项时仍要求主臂八个电机完整读取后才能启动。
原生回归工具也接受该选项，并额外检查机械臂不发生指令运动。

2026-10-23 的只读故障排查中，1–3 号电机可读出约 12.2–12.3 V、位置和温度，
Hardware Error Status 为 0；4–8 号未回复 READ/PING。若干其他波特率未找到
4–8 号。系统同时记录到 FTDI USB 断开重连；换 USB 端口后仍只能读到 1–3 号。
这些是当时的测量，不能由此断言具体电缆、供电或电机损坏。未发送力矩、
目标位置、EEPROM 写入、重启或恢复出厂指令；不能用补零伪造八轴有效样本。

## 固定主臂校准文件（2026-10-23）

模板：`scripts/teleop/config/arm_calibration.template.json`。这是明确未配置的模板，
含空值、未核对方向和 `status: unconfigured`，不能用来启用机械臂。本次开发
开始时仅 1–3 号响应，尚未制作真实校准文件；不填零代替缺失轴。
2026-10-23 16:57 再次只读检查，1–8 号全部响应，100 次完整 SYNC_READ 成功，
平均约 6.03 ms、最大约 16.03 ms，八轴 Hardware Error Status 均为 0。通信已恢复，
但逐轴方向核对和对应姿态采集仍待实际操作，未据此生成校准值。

实际标定步骤：逐轴核对方向，将两臂放到对应参考姿态，记录
同一静止参考下的七轴原始编码器弧度与仿真关节弧度；至少另取几组姿态验证方向
和对应关系。DYNA 与 Franka 连杆尺寸不同，关节角对应不等于两者末端世界位置
完全一致。本入口实现关节姿态跟随，不额外改成末端 IK。

无实体力反馈进程的关节遥操窗口提供“记录参考姿态”按钮。先重置仿真，保持
暂停，确认仿真初态就是校准文件中的参考姿态，再把实体主臂摆到对应姿态，
直接点击记录。按钮使用点击时最近的有效编码器和实测仿真角度；运行中、
超过150毫秒的样本或仿真尚未回到参考姿态时不会保存。新文件写入本次运行
目录，不覆盖旧文件，并立即用于本次仿真跟随。重启时需把 `--arm-calibration`
指向新文件。保存保留原方向标记，不证明方向正确；至少另取姿态验证，确认后
再以新文件启动重力补偿。不要用聊天回复后的任意时刻采样代替现场点击。

首次标定也可显式加 `--capture-reference-on-start`：操作者按参考图摆好，首次
点击 Start（或空格）会先现场记录零点，再开始跟随；之后的暂停/开始不再记录。
失败时保持暂停，不消耗这次记录请求。该选项仅允许无实体反馈、非自动开始的
GUI练习会话；完成后用新保存的文件正常启动，不再传该选项。
`--side-view` 将操作主相机移到机械臂侧方，便于比较弯肘姿态；只改变操作视角，
不改机器人基座、关节映射或任务资产。腕部和可选后方相机保留。

`ArmCalibration.from_reference(...)` 需要显式传入七轴方向、逐轴确认、参考角、
设备序列身份和 `source_kind`，验证原 URDF 范围后构建不可变校准；`save(path)`
保存到新的本机文件，拒绝覆盖已有文件。真实入口只接受 `source_kind: hardware`。
所有数值用弧度，方向为 ±1；对应关系为：

```text
robot_q = robot_reference + sign * (leader_q - leader_reference)
```

X-series 断电后的整圈计数可能改变。对当前 Franka 每轴小于 2π 的原始范围，
仅选择唯一处于该范围的等价角；无有效角则保持，不改变零点或扩展限位。
运行中出现整圈跳变仍按 0.35 rad 跳变保护暂停，必须重新对齐。

文件绑定稳定的 `/dev/serial/by-id` 设备名、完整 1–8 编码器顺序、七轴机器人
关节名和机械臂 URDF SHA256。换串口设备身份或机器人模型必须重新核对；
不会静默套用旧值。完整文件、内容 SHA256、接管阈值写入 session.json；
frames.jsonl 的 `arm_alignment` 保存状态及七轴误差。校准文件独立于场景初态，
日常更换场景只需重新对齐，不通过 Start 重写文件。

MANUS 在机械臂等待对齐或断流时仍可独立控制手指；界面显示机械臂等待原因。
`--manus-hand-only` 不要求机械臂校准，也不打开主臂串口。
